# 价格是怎么算出来的

一份从「厂商公布的价」到「客户被扣的 quota」的完整推导，以及每一步在哪里配、被哪个测试守着。

> 想改折扣看 `PRICING-AND-DISCOUNTS.md`（操作手册）。这份讲**为什么是这个数**。

---

## 一、三个价格，永远分开

同一个模型上有三个不同的价格，把任意两个混在一起，价目表就会烂掉——这是已经发生过的事，不是假设。

| # | 是什么 | 存在哪 | 谁能改 |
|---|---|---|---|
| 1 | **厂商官方报价** | `setting/ratio_setting/unifyapi_catalog.go`（代码） | 提 PR |
| 2 | **我们的采购成本** | `ChannelCostRatio`（按渠道） | 后台，**只用于对账** |
| 3 | **客户实付** | ① × 模型折扣 × 分组倍率 | 后台 |

**为什么 ① 必须在代码里：** 从前 ③ 是靠直接改 ① 实现的——有人把打折后的倍率填进 `ModelRatio`。这毁掉了唯一能让基线可核对的东西：当 `claude-opus-4-8` 显示 `0.2125` 时，没有任何办法区分「刻意打了 91.5% 的折」和「小数点滑了一位」。**结果是后者。**

**为什么 ② 永远不能进客户账单：** 路由是负载均衡的，同一个请求今天走 A 渠道、明天走 B 渠道。如果渠道成本影响售价，一模一样的请求会因为路由不同而收不同的钱，客户永远对不平自己的账。

## 二、客户实付：一步步推

### 起点是美元，不是倍率

目录里存的是**厂商公布的美元价（每百万 token）**：

```go
{Model: "claude-opus-4-8", Vendor: "anthropic",
 InputUSD: 5, OutputUSD: 25, CacheReadUSD: 0.5, CacheWriteUSD: 6.25}
```

倍率是**推导出来的**，不是手填的：

```
模型倍率 = 输入价 ÷ 2          （$2/1M = 倍率 1 的约定）
输出倍率 = 输出价 ÷ 输入价
缓存读倍率 = 缓存读价 ÷ 输入价
```

**为什么存美元而不是倍率：** 倍率是读不懂的形式。`2.5` 只有在你知道「$2/1M = 1」这个约定之后才等于 $5/1M，而 `0.2125` 看着完全合理。存美元，小数点滑位一眼就能看见。

### 完整公式

```
客户实付 = 官方价 × 模型折扣 × 分组倍率
                     ▲            ▲
                     │            └─ GroupRatio[分组]，或
                     │               GroupGroupRatio[用户分组][计费分组] 覆盖
                     └─ ModelDiscount[模型]，缺省 1
```

举例，`claude-sonnet-5`，100 万输入 + 100 万输出：

```
官方价        $2 + $10                      = $12.00
模型折扣 0.9  $12.00 × 0.9                  = $10.80
分组倍率 1    $10.80 × 1                    = $10.80
              ────────────────────────────────────
客户被扣                                      $10.80
```

### 折扣怎么落到账上

`applyModelDiscounts()` 把 `官方倍率 × 折扣` 重建进 `modelRatioMap`。

**下游没有任何代码知道折扣的存在**——relay、配额计算、价目页、以及每一条计费路径（文本 / 音频 / 图像 / 任务 / 分档）读的都是同一张 `modelRatioMap`，和以前一样。所以**不存在「某条路径忘了打折」的可能**。

输出、缓存读、缓存写都是**建立在模型倍率之上的乘数**，所以自动跟着缩放：打 8 折，输入、输出、缓存一起 8 折——这才是「一个模型的折扣」该有的含义。

### 两种模型走不同的路

| 情况 | 走哪 | 为什么 |
|---|---|---|
| 平价模型（49 个） | 倍率映射 | 简单，久经验证 |
| 语音价 ≠ 文本价，或有长上下文分档（9 个） | **计费表达式** | 平价映射装不下 |

表达式长这样，系数就是真实美元价：

```
len <= 256000
  ? tier("standard", p * 0.5 + c * 3 + cr * 0.05 + cc * 0.625)
  : tier("long_context", p * 2 + c * 6 + cr * 0.2 + cc * 2.5)
```

⚠️ **分档计费走分组倍率，但完全不碰 `modelRatioMap`。** 所以表达式的系数里**必须把折扣烘进去**，否则那 9 个模型会照标价卖，而后台还显示着折扣。`RebuildRatioMapsFromCatalog()` 在折扣表变动时重新生成它们，两档都打折——只打基础档等于恰好对最贵的长请求多收钱。

### 最后一步：美元变 quota

```
quota = 美元 × QuotaPerUnit        （默认 500000）
```

分档表达式那条路多一步单位换算：

```
quota = 表达式输出 ÷ 1,000,000 × QuotaPerUnit × 分组倍率
```

表达式的输出是**美元 × 100 万**（系数是每百万价、token 是原始个数）。写测试时按原样当美元断言，会「证明」一个差 100 万倍的账单——这个坑我踩过。

## 三、上游成本：**建模**出来的，不是读出来的

```
上游成本 = 官方价 × 该渠道的采购倍率
```

**为什么是建模：厂商不出逐请求收据。** 所以这个数是估算，而对账的全部意义就是拿它去和厂商月底的账单对差：差得小说明模型对，差得大就是一个发现。

采购倍率按**渠道**配，不按模型——转售合同基本都是「官方价打 N 折」，一个数就够，而且厂商调价时它依然成立。

**没配的渠道默认 1（按官方价买）。**这是保守的：只会低估毛利，不会高估。但也意味着——

> 采购倍率没填之前，毛利数字是**未测量**，不是零。利润页会明说这一点，而不是把整张表刷成红色。

## 四、两侧为什么必须独立推导

| | 收入 | 成本 |
|---|---|---|
| 来源 | **读**消费日志 | **算**：token × 官方价 × 采购倍率 |
| 可信度 | 就是客户被扣的钱 | 估算，待验证 |
| 能不能重算 | **不能** | 本来就是算的 |

**收入绝不重算。** 账本里的 quota 已经包含了当时的折扣、分组倍率、缓存计价和各种钳制。重算意味着客户账单可能和他自己看到的扣费对不上——而那是唯一让这份账单在争议时站得住的性质。

有一条测试专门守这个边界：`TestACustomerDiscountNeverMovesUpstreamCost` —— 给某个模型打 9 折，逐个断言上游成本**一分不动**。如果折扣泄漏进成本模型，不管我们卖多便宜毛利都会显示健康，两边就变成互相印证，毛利数字彻底失效。

（这条测试是用变异验证过的：把折扣注入成本函数，它会按模型名报错。）

## 五、哪些东西守着这些数

| 层 | 守什么 | 文件 |
|---|---|---|
| **漂移检查** | 目录 vs **厂商公布价** | `scripts/pricing-drift` |
| **写死的美元** | 账单 vs **手抄的厂商价** | `TestPinnedDollarsForTheModelsThatCarryTheTraffic` |
| **全量扫描** | 账单 vs 目录（49 个模型逐个） | `TestEveryModelChargesItsOfficialPriceTimesItsDiscount` |
| **折扣响应** | 每个模型都真的吃折扣 | `TestEveryModelRespondsToItsDiscount` |
| **两侧独立** | 折扣不得影响成本 | `TestACustomerDiscountNeverMovesUpstreamCost` |
| **基线覆盖** | 渠道上每个模型都有价 | `TestServedButUnsellableModelsAreDeclaredAndRefused` |
| **折扣表完整** | 应用时不会抹掉任何模型 | `TestPayloadCoversEveryServedModel` |

**为什么需要前两层而不是只要第三层：** 全量扫描的期望值是**从目录算出来的**，所以它对目录的**数值**是自我印证的——我把 `gpt-4o` 的输入价从 $2.50 改成 $0.25，它照样通过。数值错误由漂移检查和写死的美元抓，两者对同一个变异都会失败。

**为什么漂移检查也不够：** models.dev 是聚合站，会滞后。DeepSeek 在 2026-08-16 涨价，它挂着旧价 **17 天**——期间漂移检查一路绿灯，而我们在亏本卖。所以目录多了 `QuoteSource` / `QuoteDate`：**手抄自厂商自己页面、带日期的报价，优先级高于 feed**。

## 六、一次完整的推导（真实数字）

`deepseek-v4-pro`，100 万输入 + 100 万输出，2026-08-31 起：

```
厂商公布（峰值档）      $1.32 入 + $3.96 出          = $5.28
                       ↓ × 模型折扣 0.7
客户实付                                              = $3.696
                       ↓ × 分组倍率 1
最终扣费                $3.696 × 500000 quota/$      = 1,848,000 quota

上游成本（采购倍率未配 → 按官方价）                    = $5.28
毛利                    $3.696 − $5.28               = −$1.584
```

最后一行正是那个必须说清楚的地方：**在采购倍率填进去之前，这个「亏损」是建模假象，不是事实。** 真实毛利取决于你和 DeepSeek 谈下来的价。
